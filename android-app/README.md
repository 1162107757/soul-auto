# SoulBot 自动助手

SoulBot 是一个运行在 Android 手机上的 Soul 聊天自动化助手。它通过无障碍服务识别 Soul 当前页面、读取可见聊天内容并执行点击、滑动和输入，通过 OpenAI 兼容接口调用大模型生成回复；运行状态、下一步动作和倒计时由可拖动的悬浮控制器展示。

> 本项目仅用于个人设备上的自动化研究与辅助操作。请遵守 Soul 的服务条款、当地法律法规和聊天对象的意愿。自动化操作可能触发平台风控或账号限制，使用者需自行评估并承担相关风险。

## 主要功能

- 两套相互独立的自动化模式：**星球与聊天**、**广场与私聊**
- 奇遇铃最高优先级处理，随后处理新招呼和未读聊天，再执行当前模式的空闲任务
- 只处理带未读标识的会话和语音，避免反复回复已处理内容
- 结合多段聊天上下文、个人资料、联系人记忆和本地聊天风格生成回复
- 对“嗯、哦、对、哈哈”等低信息消息回看更早上下文，不只针对最后一句机械作答
- 控制提问频率，避免连续抛问题形成“查户口”式聊天
- 灵魂匹配成功后，根据引力签生成开场白；没有引力签时使用昵称和星座兜底
- 同城广场稳定扫描、慢速翻页、帖子与用户绑定、同轮和跨轮打招呼去重
- 未成功发送广场私信时继续尝试，至少成功发送一条后才进入私信冷却
- 未读语音自动触发 Soul 的“转文字”，等待文字稳定后再生成回复
- 最多配置 5 个模型端点，按 P1–P5 优先级自动切换、冷却和恢复
- 每个联系人的完整聊天记录保存在本机，可查看、导出、合并导入和清空
- 悬浮窗展示运行状态、下一步动作及剩余秒数，支持拖动和贴边自动收纳
- 根据 Soul 有效窗口和列表容器动态计算点击、滑动与消息方向，适配不同分辨率、DPI 和系统栏
- 提供设备适配诊断页，被动记录各 Soul 页面能力，并按设备与 Soul 版本保存语音菜单兜底位置
- 持久化记录任务、页面、发送、语音、模型切换和异常现场，可在应用内查看并导出诊断日志
- 工作线程异常退出时可自动恢复；手动停止后不会自行重启

## 自动化模式与优先级

### 星球与聊天

该模式只执行以下任务：

1. 回复新招呼和聊天列表中的未读消息。
2. 没有未读消息时进入星球并发起灵魂匹配。
3. 匹配成功进入聊天页后，优先回复对方已发来的消息；没有消息时，根据引力签生成开场白。
4. 页面没有引力签时，使用对方昵称、星座或二者组合生成自然开场白。
5. 消息成功发送后才离开当前会话；回到星球且没有新消息时继续匹配，不在星球页空等聊天消息。

此模式不会浏览广场或主动私信广场用户。

### 广场与私聊

该模式只执行以下任务：

1. 回复新招呼和聊天列表中的未读消息。
2. 没有未读消息且达到私信间隔时，切换到**同城广场**浏览帖子。
3. 将帖子文字、头像和用户绑定到同一卡片，基于该帖生成开场白并私聊对应用户。
4. 当前屏幕内容稳定后才选择目标；翻页使用较慢的短距离滑动，减少遗漏。
5. 同一轮不重复私聊同名用户，历史去重规则同时避免跨轮重复打扰。
6. 遇到礼物门槛、“今日自闭中”等无法发送的场景会退出并继续尝试其他目标。
7. 至少成功发送一条私信后才开始广场私信冷却；全部尝试失败不会误入冷却。

此模式不会发起灵魂匹配。

### 全局任务优先级

两种模式共用同一套抢占顺序：

1. **奇遇铃弹窗**：出现后立即优先处理，根据签名、匹配理由或引力签生成开场白并私聊。
2. **新招呼与未读聊天**：只打开带未读标识的会话；多人同时来消息时串行处理，并在发送前复核联系人和最新消息。
3. **模式空闲任务**：星球与聊天执行灵魂匹配，广场与私聊执行同城广场私信。

## 回复生成策略

### 上下文与自然度

- 读取当前会话的多段可见上下文，不只取最后一句。
- 对低信息回复结合前文主题继续接话。
- 对方询问性别、年龄、地区、星座、职业等信息时，优先使用“我的资料”中已填写的内容；未填写的字段不会凭空编造。
- 可引用该联系人的历史聊天记忆，保持跨会话连续性。
- 可从用户手动发送的聊天样本中提取平均长度、表情和提问习惯；程序自动生成的回复会被标记，不会反过来污染学习样本。
- 过滤模型思维链、模板化措辞、重复内容和明显不合格回复；连续出现质量问题时可切换备用模型。
- 回答对方明确问题时优先把问题答完整，不强行立即反问。
- 开场或话题需要延续时可抛一个轻量“引子”；如果最近回复已经连续提问，则改用陈述或分享，避免每句都问。

程序只在确认发送成功后将消息标记为已处理。若生成期间收到新消息，会重新读取会话并基于最新内容生成，避免把旧回复发给错误联系人。

### 未读语音转文字

1. 只查找带红点的对方未读语音气泡。
2. 优先点击气泡附近的“转文字”；必要时使用长按菜单和坐标兜底。
3. 将转写结果按节点归属和屏幕位置绑定到对应语音气泡。
4. 等待转写文字连续稳定后再生成回复。
5. 转写失败时不使用旧上下文猜测回复，也不将该语音标记为已处理，留待后续重试。

语音识别本身由 Soul 客户端提供，Soul 未提供“转文字”、网络异常或无障碍节点不可见时，程序无法取得语音内容。

## 多模型配置与故障切换

“模型与 API”页面最多可维护 5 个模型端点。每个端点包含：

- 配置名称和服务商
- OpenAI 兼容 API 根地址
- 模型名称
- API Key
- 启用状态

内置预设包括 DeepSeek、智谱 GLM、Kimi、通义千问、OpenAI 和自定义中转站。自定义地址应填写 API 根地址，不要包含 `/chat/completions`。

已启用端点按列表中的 P1–P5 顺序调用，可通过上移、下移或拖动调整优先级，也可单独测试：

- 单个端点最多等待 30 秒，一轮生成总计最多等待 75 秒。
- 当前端点失败后，等待 3 秒再切换到下一可用端点。
- 临时错误从 30 秒开始指数冷却，最长 10 分钟。
- 限流错误优先采用响应中的 `Retry-After`，否则默认冷却 60 秒。
- 地址、Key、模型名等配置错误会将该端点标记为“需修复”，修改配置后再恢复。
- 同一端点连续两次生成内容被质量校验拒绝时，会暂时切换到备用端点。

悬浮窗会显示当前调用的优先级、模型、切换原因和倒计时。模型测试和正式生成都会消耗对应服务商的额度。

## 设置页面

主界面是状态仪表盘，展示当前运行状态、权限、任务模式、可用模型、个人资料完整度、本地记忆及设备适配统计。详细配置拆分为六个页面：

| 页面 | 主要内容 |
|---|---|
| 任务设置 | 自动化模式、广场私信间隔、回复延迟范围、打招呼去重间隔 |
| 模型与 API | 新增、编辑、启停、排序、删除和测试最多 5 个模型端点 |
| 我的资料 | 性别、年龄、地区、星座、职业及补充说明 |
| 回复与学习 | 聊天风格学习、联系人记忆引用、样本统计及清理 |
| 数据与备份 | 联系人/消息统计、历史查看、聊天记忆导出、导入及清空 |
| 设备适配与诊断 | 屏幕参数、最近 Soul 页面、累计识别能力、本机兜底记录，以及运行日志查看与导出 |

默认时间配置如下：

| 配置项 | 默认值 | 说明 |
|---|---:|---|
| 广场私信间隔 | 240 秒 | 仅“广场与私聊”模式使用，并从成功私信后开始计时 |
| 回复延迟 | 5–15 秒 | 新消息的随机思考时间；超过约 1 分钟的旧消息不再额外等待 |
| 打招呼去重间隔 | 24 小时 | 同一用户出现新帖子后再次私聊所需的最短间隔；相同帖子不会重复私聊 |
| 聊天风格学习 | 开启 | 从人工回复样本中提取表达习惯 |
| 联系人记忆 | 开启 | 生成回复时参考该联系人的历史信息 |

切换自动化模式后，停止并重新开始任务即可按新模式运行。

## 悬浮控制器

- 点击“启动悬浮按钮”后显示悬浮控制器，再点击其中的“启动”开始任务。
- 运行时展示当前状态、下一步准备执行的动作和剩余秒数；停止按钮始终可见。
- 控制器可拖到任意位置。拖到屏幕边缘后，停留 5 秒会自动收纳为小圆形手柄；点击手柄重新展开并重新开始 5 秒计时。
- 如果用户把控制器拖离屏幕边缘，它会停留在该位置，不会自动吸附或收纳。
- 收纳状态不显示展开箭头，仅用运行/停止图标表达状态。
- 无障碍工作线程意外退出时，若任务开关仍为运行状态，会在短暂等待后恢复；用户主动停止会清除运行意图，不会自动重启。

## 本地聊天记忆与备份

程序按联系人保存每条消息的方向、内容、时间、来源和去重标识。进入可见会话时会同步聊天记录，程序自动发送的内容也会写入数据库。开启联系人记忆后，生成回复时可检索该联系人较早的相关消息。

“数据与备份”页面支持：

- 查看联系人数量、消息数量和互动历史。
- 导出为 `soulbot-chat-memory-<时间戳>.json`。
- 从 JSON 或纯文本文件导入；导入采用合并方式，新增记录并跳过重复项，同时报告无效记录。
- 确认后清空本机完整聊天记忆。此操作不会删除 Soul 客户端中的聊天内容。

导出文件是包含聊天内容的明文文件，请妥善保管，不要上传到不可信平台。API Key 不包含在聊天记忆导出文件中。

## 运行日志与问题分析

进入“设备适配与诊断 → 运行日志”可以查看最近运行现场，并将完整诊断日志保存为 UTF-8 文本文件。日志覆盖：

- 应用、无障碍服务、悬浮服务和工作线程的启动、停止、异常退出与自动恢复。
- 页面切换和卡页检测、未读扫描、广场每屏扫描及私聊结果。
- 消息输入、发送点击、发送确认，以及语音转文字采用的路径、耗时和失败原因。
- 模型调用顺序、耗时、HTTP 状态、失败类型、冷却切换和回复质量校验结果。
- 未捕获异常的类型、消息及有限长度堆栈。

日志按分类、级别、进程会话和序号记录，单个文件约 512 KB，最多保留当前文件和 4 个历史文件。日志位于 Android 的 `noBackupFilesDir/logs`，不会参与系统自动备份；旧版日志会在首次使用时迁移。联系人使用仅在本次安装内有效的匿名 ID，API Key、Authorization、Bearer Token、URL 密钥等会在写入和导出时再次脱敏，程序不会主动把完整聊天正文写入运行日志。

导出的文件会附带应用版本、Android/Soul 版本、屏幕参数、权限状态、自动化模式、模型通道数量和最近页面，便于复现问题。诊断文件仍可能暴露设备与运行行为信息，请只发送给可信人员。日志页也支持二次确认后清空全部滚动日志。

### 本地存储

| 存储 | 用途 |
|---|---|
| `conversation_memory.db` | 按联系人保存完整聊天消息，为历史查看、上下文记忆和导入导出提供数据 |
| `chat_learning.db` | 人工风格样本、旧版联系人摘要和自动回复标记 |
| `greet.db` | 广场用户、帖子内容和打招呼时间，用于去重 |
| `history.db` | 兼容旧版互动记录及简要历史展示 |
| `soulbot_prefs` | 任务模式、时间参数、个人资料、模型端点、API Key 和运行状态 |
| `noBackupFilesDir/logs/runtime-events.log*` | 脱敏后的结构化运行日志和 4 份滚动历史，不参与系统自动备份 |

以上数据库和设置位于 App 私有目录。卸载 App 或清除应用数据会删除它们；重要聊天记忆请提前导出。

## 构建、测试与安装

在 `android-app` 目录执行：

```powershell
# Windows PowerShell
.\gradlew.bat testDebugUnitTest assembleDebug lintDebug
```

```bash
# macOS / Linux
./gradlew testDebugUnitTest assembleDebug lintDebug
```

Debug APK 输出位置：

```text
app/build/outputs/apk/debug/app-debug.apk
```

已配置 ADB 且手机允许 USB 调试时，可直接覆盖安装：

```powershell
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

也可以使用 Android Studio 打开 `android-app` 目录后运行 `app` 模块。单元测试覆盖任务模式、模型端点与故障策略、回复上下文、联系人记忆、去重、语音归属、灵魂匹配内容和悬浮状态格式等纯逻辑模块。

## 首次使用

1. 安装并登录 Soul，确认星球、广场和聊天功能可以手动使用。
2. 安装并打开 SoulBot。
3. 在“模型与 API”中至少添加并启用一个配置完整的模型，使用“测试”确认接口可用。
4. 在“我的资料”中填写希望程序被问到时采用的真实信息；不希望回答的字段留空。
5. 在“任务设置”中选择“星球与聊天”或“广场与私聊”，按需调整时间参数。
6. 在系统设置中开启 **SoulBot 自动助手**无障碍服务，并授予悬浮窗权限。
7. 首次在新手机使用时，可进入“设备适配与诊断”，打开 Soul 并依次停留在聊天列表、聊天、星球和同城广场页面，确认关键能力已被识别；此过程不会启动自动任务。
8. 返回主界面启动悬浮按钮，在 Soul 前台点击悬浮窗中的“启动”。
9. 通过悬浮窗观察当前动作和倒计时；需要接管手机时先点击“停止”。

## 已知限制与排查

1. **Soul 改版可能导致识别失效**：自动化依赖 `cn.soulapp.android:id/...` 控件 id、文本特征和节点位置；Soul 更新布局后可能需要同步调整。
2. **仅处理无障碍可见内容**：图片、表情包或未暴露文字的复杂卡片不一定能被准确理解。
3. **语音依赖 Soul 转写**：没有“转文字”入口、转写失败或文字节点未暴露时，不会猜测语音内容。
4. **同名联系人可能混淆**：当前主要使用聊天页昵称作为联系人记忆和部分去重键，同名用户需要人工留意。
5. **设备后台限制**：部分厂商系统会回收前台服务、关闭无障碍或限制自启动，需在系统电池与后台管理中允许 SoulBot 运行。
6. **特殊布局仍需验证**：常见手机分辨率、DPI、状态栏和导航栏由自适应层处理；分屏、横屏、折叠屏和平板若触发 Soul 的另一套页面结构，仍应先运行设备诊断并进行真机验证。
7. **模型兼容差异**：接口必须兼容 OpenAI `POST /chat/completions`；不同中转站的错误码、超时和响应格式可能存在差异。
8. **隐私与密钥**：API Key 保存在 App 私有 SharedPreferences 中；无障碍服务可读取屏幕上的聊天文字，聊天备份又是明文文件，请只在可信设备上使用并保护导出文件。
9. **平台风控**：频繁匹配、滑动或主动私信仍可能被判定为异常行为。建议使用合理间隔，并通过悬浮控制器持续观察运行状态。

如果任务表现异常，先停止悬浮任务，再依次确认：无障碍服务仍开启、悬浮窗权限正常、Soul 当前处于已登录状态、至少一个模型端点可用且未在冷却、网络连接正常。随后重新启动任务，并根据悬浮窗显示的“下一步”判断卡在页面识别、语音转写还是模型调用阶段。
